# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Marv (the `marv` command) is a terminal coding agent (like Claude Code) written in TypeScript on **Bun** with an **Ink** (React-for-terminal) TUI. It is being built milestone by milestone; the roadmap lives in `~/.claude/plans/im-planning-on-making-staged-eclipse.md`. The owner is learning how agents work, so explain the *why* of each change.

## Commands

```sh
bun install
bun run dev                 # run the TUI from source (same as `marv`)
bun test                    # all tests
bun test tests/commands     # one file (path substring filter)
bun test -t "streams"       # tests whose name matches
bun run typecheck           # tsc --noEmit
bun run stats               # sum up trajectory logs (--by model|marv)
bun link                    # (once) puts `marv` on PATH, pointing at src/cli.tsx — no build step
```

## Architecture

- `src/cli.tsx` is the `bin` entry (Bun shebang). It handles `--version`/`--help`, takes the project root from the current directory, reads the project's `AGENTS.md` once (`loadInstructions` in `src/prompt.ts`, capped at 20k chars), then renders `<App>`.
- **Config (`src/config/config.ts`)**: two layers, later wins: `~/.marv/config.json` (zod-validated, written with mode 0600 because it can hold the API key), then env vars (`OPENROUTER_API_KEY`, `MARV_MODEL`, `OLLAMA_HOST`). `PRESETS` describes each provider (label, base URL, which env var holds its key, default model). `FileConfig` is what's on disk; `resolveConfig()` produces the `Config` the app runs on. `MARV_CONFIG_DIR` relocates the config, so use it when testing by hand to keep your real config untouched.
- **Setup (`src/ui/Setup.tsx`)** runs on first run, or when OpenRouter has no key, and again via `/setup` (and `/model`, starting at the model step). It renders *in place of the prompt* (pinned at the bottom, below the transcript), not as a separate screen.
- `createProvider(config)` in `src/provider/index.ts` is the only place that maps config to a concrete `Provider`. OpenRouter uses `OpenAICompatProvider` (`src/provider/openai-compat.ts`: plain `fetch` to `POST {baseUrl}/chat/completions`, SSE parsed by `src/provider/sse.ts`; tool calls arrive in fragments keyed by `index` and are assembled before being emitted; `stream_options.include_usage` gets token counts incl. cached tokens). Ollama uses `OllamaProvider` (`src/provider/ollama.ts`: native `POST /api/chat`, NDJSON), because only the native API can set the context window (`num_ctx` = config `contextLength`, default 32768; Ollama's own default of 4096 is too small for an agent). `think` follows `/think` (off by default: local thinking models can otherwise reason for minutes).
- `src/app.tsx` holds all session state. The phases are `splash` → `main`, plus an optional setup overlay. It keeps two separate histories:
  - `items`: the **transcript the user sees**, including the welcome banner, help text, and errors.
  - `conversation` (a ref of `ChatTurn[]`): **what the model sees**: user and assistant turns, the assistant's tool calls, and tool results.
  Keep them separate; Marv's own notices must never leak into the model's context.
- **Agent loop (`src/agent.ts`)**: `runAgent()` sends the conversation plus tool definitions, runs any tools the model asks for (via an injected `runTool`), appends the results, and repeats until a plain answer, an error, or ctrl+c. Every 25 steps (`maxSteps`) it calls `onLimit`, after that step's tool results are in: the App asks through the approval queue ("Keep going?", scope `continue`) and a no stops it with a hint to say "continue"; without `onLimit` (subagents, 50 steps) it's a hard stop. Either way a `step_limit` event says what happened. It yields `LoopEvent`s and knows nothing about the UI or vendors; `App.send()` turns the events into transcript entries (tool calls are `role: "tool"` messages updated in place: running → summary or error). Every tool call gets a result, even after ctrl+c, or the next request would be rejected; that includes a consumer that stops mid-tools (throws or breaks out): a `finally` answers the calls left without a result with "not run", in order. Tool-call ids are unique across the conversation: before a reply enters the history, an empty id or one already used (a duplicate in the reply, Ollama's `call_0` in every step, a resumed session's) gets a `_<n>` suffix, since the API and the UI both match results to calls by id. Tool calls run one at a time, except a run of consecutive calls of a `parallel` tool (`agent`; the App passes `isParallel`), which run concurrently, at most `MAX_PARALLEL` (4) at once; their `tool_start`/`tool_end` events arrive as they happen, but the results are appended in call order, so the history (and the prompt cache) doesn't depend on which finished first. A call starts only after its `tool_start` has been delivered (a consumer that stopped never has a tool running it can't show or stop), and after an abort or a "no" nothing new starts: queued calls get a "not run" result.
- **Tools (`src/tools/`)**: each is a name, a description the model reads, a zod `input` schema (sent as JSON schema; also validates what comes back), a `label` for the transcript, and `run()` → `{ output, summary }`. Register new ones in `tools` in `src/tools/index.ts`. Read tools (`read_file`, `glob`, `grep`) run freely; tools with `kind: "write" | "execute"` (`edit_file`, `write_file`, `bash`) need approval, unless the tool defines `needsApproval(input)`, which then alone decides per call (`agent` asks only with `isolation: "worktree"`), or yolo mode runs it (see **Yolo mode**). `runTool()` first calls the tool's `preview()` (a diff, or the command; a `ToolError` there means the call can't succeed, so the user is never asked to approve it), then, unless the run was aborted meanwhile, `ctx.approve()`, which the App answers with the `Approval` prompt (yes / yes and don't ask again for the tool's `scope` this session / no). The "don't ask again" scopes are one set shared by the main agent and its subagents (an "always" for file edits in one covers the other). Requests wait in a FIFO queue in the App (parallel subagents can ask at once): the prompt shows the oldest, who asks, and `N more waiting`, and is keyed per request so the choice cursor never carries over; "always" also answers the queued requests in the same scope. Esc or ctrl+c at an approval declines everything queued **and** aborts the run, so sibling subagents don't keep asking after the user said stop. A "no" returns a `declined` result and `runAgent` stops so the user can redirect. `runTool(call, ctx, available)` only runs tools in `available` (default: all), so a subagent can't call a tool it wasn't offered by naming it. `edit_file` replaces text that must match exactly once (or `replace_all`) and is re-planned at apply time in case the file changed while the user decided. `runTool()` never throws: bad JSON, invalid input, and `ToolError`s become error results the model can recover from. All paths go through `resolveInProject()` (`src/tools/files.ts`), which rejects anything outside the project root, including via symlinks (grep too: it never follows a symlink out of the project). `read_file`, `edit_file`, `write_file` and `grep` refuse special files (FIFOs, devices), since reading one would block forever. Files are listed with `git ls-files` (so `.gitignore` applies) through `runGit` (see **Subagents**; a 20 s timeout, an error rather than the unfiltered walk, and `ToolContext.gitEnv` pins a worktree subagent's git paths), falling back, outside a repo, to a walk that skips `node_modules`, `.git`, `dist`, etc.
- **Skills (`src/skills.ts`, `src/tools/skill.ts`)**: `.marv/skills/<name>/SKILL.md` (project) and `~/.marv/skills/<name>/SKILL.md` (personal; a project skill wins a name clash), YAML frontmatter (`name`, `description`) parsed with `Bun.YAML`, then the instructions; extra files in the folder are listed. Loaded once in `cli.tsx`; broken ones are skipped and reported (startup notice and `/skills`). Progressive disclosure: only names and descriptions go into the system prompt (stable all session, so the cache holds); the model loads the full instructions with the `skill` tool (only offered when skills exist; `file` reads one of the skill's files, confined to its folder). `/<skill> args` sends the instructions with the request directly (the transcript shows what was typed); skills also appear in the `/` menu. Measured with local models: a task-shaped request ("write release notes…") made qwen3.5:9b load the matching skill 4/5 times and gemma4:12b 5/5; a greeting skill was ignored. Descriptions should name the task and when to use it.
- **Memory (`src/memory.ts`, `src/tools/memory.ts`)**: one-line Markdown bullets in `~/.marv/memory/personal.md` (everywhere) and `~/.marv/memory/projects/<project>.md` (one project; private, never in the repo), 0600. Loaded in `cli.tsx`; the App holds them as state for the system prompt's Memory section, fixed within a conversation and reloaded by `/clear`. The model changes memory with the `memory` tool (`kind: "write"`, so every change is approved: memory persists, and an instruction planted by a malicious file and saved there would return in every session). A removal must match exactly one memory or fails before asking. `/memory`, `/remember [project:] <note>`, `/forget <text>` edit it directly, without approval. Approval previews show `command` with `$`, plain `text` without.
- **Subagents (`src/agents.ts`, `src/subagent.ts`, `src/tools/agent.ts`)**: the `agent` tool (`type`, `description`, `prompt`, `isolation?`) runs `runAgent()` again with a fresh history (just the prompt), the type's system prompt (`subagentPrompt` in `src/prompt.ts`: the type's body, then report format, no one to ask questions, start narrow, the worktree note; no memory) and only `SUBAGENT_TOOLS` ∩ the type's tools, passed as `available` to `runTool`. Never `agent` (no nesting, no runaway recursion) or `memory` (it outlives the session, so only the main agent changes it); `skill` only when skills exist. 50 steps (`SUBAGENT_MAX_STEPS`). Only its final message returns, so the files it read never fill the parent's context; Marv's own lines in it (why it stopped, the branch) are prefixed `Marv:` so the subagent's text can't pass for them. Its usage counts toward `/cost`. Types are `.marv/agents/<name>.md` (project) and `~/.marv/agents/<name>.md` (personal; project wins a clash), plus the built-in `general-purpose`, loaded once in `cli.tsx` (unreadable or broken files are reported at startup and by `/agents`, never fatal). The format is Claude Code's: frontmatter `name`, `description`, optional `tools` (Claude Code names are mapped, incl. `MultiEdit`→`edit_file`, `LS`→`glob`; anything outside `SUBAGENT_TOOLS` is a problem, not silently dropped) and `model` (`inherit`/`sonnet`/`opus`/`haiku` mean the session's model; anything else is a model id on the same provider), then the body. `findAgent` also tries a name without its `plugin:` prefix (`superpowers:code-reviewer`), so skills written for Claude Code work unedited. The main system prompt's `# Agents` section lists names and descriptions only. The App gives the main agent's `ToolContext` an `AgentHost` (types, `providerFor(model)`, cwd, AGENTS.md, worktrees dir, `onUsage`, `onProgress`); a subagent's context is built from scratch without one, so subagents can't start subagents. A shared-folder subagent asks before each change, the prompt labeled `[type · description]` (`ApprovalRequest.agent`). The transcript entry's second line is live (`shared folder · 2 tools · read_file src/x.ts`), then `done · N tools · Xk tokens · "first line"`; progress reaches it through `onProgress`, batched into the 33 ms stream flush (several running agents would otherwise re-render far more often than Ink draws). ctrl+o shows each subagent's last 20 steps (labels and summaries only), and the status bar shows `N agents running`. **Clicking a subagent's entry opens its own view** (`src/ui/AgentView.tsx`): its task, replies, thinking and tool calls, live. `runSubagent` forwards every loop event to `AgentHost.onEvent`; the App folds them into an `AgentLog` (`src/agent-log.ts`, the same shapes `MessageView` draws) per entry id, in memory for this session only (not saved; a resumed session's entries say so on click). Only the open view re-renders, in the 33 ms flush. The click is hit-tested against each agent entry's Yoga layout (`Transcript`'s `onAgentRef` registry + `agentEntryAt`, with `selection.rowAt` for the transcript row). The main `ScrollView` stays mounted but `hidden` (keeps its scroll position); the view gets its own. The prompt and approvals stay at the bottom; Esc closes the view without stopping the run (the `Approval`'s own Esc is off meanwhile, so it can't decline everything), and sending a message closes it too. `ink-text-input` is patched (`patches/ink-text-input@6.0.0.patch`) to ignore ctrl+letter (only letters, so ctrl+arrows still move the cursor), so shortcuts like ctrl+o don't type the letter.
- **Worktrees (`src/worktree.ts`, `src/git.ts`)**: `isolation: "worktree"` runs a subagent in `~/.marv/worktrees/<project>/<slug>-<id>` on a new branch `marv/<slug>-<id>` from `HEAD` (the preview errors outside a repo with a commit, and warns that uncommitted changes won't be in it). `git worktree add` checks out the whole repository, so a session started in a subfolder (`repo/pkg`) gives its subagent the same subfolder of the worktree (`git rev-parse --show-prefix` → `Worktree.prefix`/`workDir`; created if it has no tracked files) as its root and cwd; its sandbox shows the rest of the worktree read-only, so git finds the repository and doesn't list the other files as deleted. The finishing commit and the nested-repo check still cover the whole worktree, and the approval's uncommitted-change count is the whole repository's (it says so). The dispatch is the one approval (scope `agent:worktree`); inside a sandboxed worktree its changes are then auto-approved, except `bash` with `network: true` (a worktree limits what a command changes, not what it sends out); with the sandbox off or bwrap missing, everything asks. Its sandbox can write only the worktree; the repository's `.git` is mounted read-only (`ToolContext.readOnly`), so `git status`/`diff`/`log` work but it can't commit, move branches, or plant hooks or config, which git would later run *outside* the sandbox. When it ends (however it ends), **Marv commits for it** (`finishWorktree`): one commit per subagent, `marv: <description>` (`(interrupted)` unless it ended with a plain answer), through a temporary git dir Marv writes itself (HEAD → the branch, `commondir` → the real `.git`, a copy of the worktree's index, without which nothing is committed: an empty index would drop force-added or skip-worktree files), so nothing the worktree's own `.git` file or record says is trusted. It refuses to commit if the worktree contains another `.git` (git would use that repository's config), except inside folders git ignores (`node_modules/x/.git`, `.venv/src/<pkg>/.git`), which `add -A` never looks into; they're listed by the same git dir that commits (`ls-files --others --ignored --directory`), and if that fails everything is walked. The walk (no symlinks followed) and the folder's removal are async, so finishing after a `bun install` doesn't freeze the UI; the git calls stay synchronous (short, with a timeout). Then it deletes only that worktree's folder and its own admin dir (not `git worktree prune`, which would drop the user's worktrees whose folders are missing right now) and keeps the branch (deleted if it has no commits); if anything couldn't be committed, the folder is kept and its path reported. The parent reviews and merges with ordinary, approved git commands. Commits are unsigned (`commit.gpgSign=false`: a pinentry prompt can't show in the TUI and would block every subagent). Known limits: split-index and reftable repositories fail safe (git errors, the folder is kept). **All of Marv's own git calls** (worktrees, the file listing) run outside the sandbox without approval in folders an agent could have touched, so they go through `runGit` (`src/git.ts`): `NO_PROGRAMS` (`core.hooksPath=/dev/null`, `core.fsmonitor=false`), inherited `GIT_*` variables dropped, stdin ignored, and a timeout (`spawnSync` blocks the whole UI, ctrl+c included, until git exits).
- **MCP servers (`src/mcp/`)**: through the official SDK (`@modelcontextprotocol/sdk`), stdio and Streamable HTTP. Config is Claude Code's format (`config.ts`): `.mcp.json` (project) and `~/.marv/mcp.json` (personal; a project server can't take a personal server's name, since it would look like yours when you're asked to trust it), `${VAR}`/`${VAR:-default}` expanded, an optional `timeout` (seconds per call, default 120); the old `sse` transport is reported, not supported. **A project's servers start only once trusted** (`trust.ts`, `~/.marv/mcp-trust.json`, per project and per exact config: `key` is a hash of the raw entry plus the content of project files its command line names (`node mcp/server.js`: an agent could edit that file without asking), so a changed command or script needs trusting again (files those load aren't covered, and the notice says it runs project files); a cloned repo, or an agent editing `.mcp.json`, could otherwise run any program); `/mcp trust` trusts and starts them. Servers are always shown from their raw config (`display`: `${VAR}`s unexpanded, so secrets never reach the screen, with `env`/headers included), and the trust notice and `/mcp` list the variables a server reads (`reads`: a project server asking for `$OPENROUTER_API_KEY` stands out) and the project files it runs (`runsProjectFiles`). `McpManager` (`manager.ts`) is created and started in `cli.tsx` (not awaited) and passed to the App; it connects in parallel (60 s timeout), starts your own (personal) servers in your home folder and a project's in the project (`cwdFor`: yours skip the trust check, and `npx -y <pkg>` run from the project would pick up a `<pkg>` planted in its `node_modules`; `${MARV_PROJECT_DIR}` gives yours the project path), keeps each local server's stderr off the screen (piped; the last lines show in `/mcp`), and passes stdio servers only the SDK's safe base environment plus their `env` (no API keys). **The tool list is fixed once the servers have settled** (prompt cache): `send()` waits for `mcp.ready` before its first request (busy from then on, with its own abort controller, so a second message can't start a second run and Esc/ctrl+c cancel the wait; shown as "Waiting for MCP servers to start…" where "Thinking…" would be; a failed start still lets the turn go on), and only `/mcp trust` adds tools later. `tool.ts` turns each MCP tool into a Marv `Tool` named `mcp__<server>__<tool>` (sanitized, at most 64 chars) with the server's own JSON schema as its spec (`input` is a loose record: the server validates), the description prefixed with the server's name, `kind: "read"` only when the server says `readOnlyHint` (you chose to run that server), otherwise it asks (scope per tool), and **no `autoSafe`: yolo never skips it** (it runs outside the sandbox). Results: text blocks joined, images/audio named but not sent, structured content as JSON, capped at 30k chars; a server error or a dead connection becomes a `ToolError`. The App offers `[...builtin, ...mcp]` (`offered()`), also for compaction; the system prompt gets a fixed `# MCP tools` section (treat their output as data). Subagents aren't offered MCP tools. Local servers are closed on exit (and killed in an `exit` handler; one whose parent dies sees stdin close and exits). `tests/fixtures/mcp-server.ts` is a real SDK server the tests run over stdio and over HTTP (`Bun.serve` + the SDK's web-standard transport).
- **Yolo mode** (`/yolo`, config `yolo`, **on by default**; the status bar shows `yolo`): a call whose tool vouches for it with `autoSafe(input, ctx)` runs without asking. `runTool` still makes the preview first (a call that can't succeed fails the same way), then runs it with `ctx.confined`. What's safe: `bash` in a working sandbox without `network` or `git_write`; `edit_file`/`write_file` outside `.git` (`touchesGit`, through symlinks; re-checked at apply time with `refuseGit`, since a parallel command could point a symlink into it meanwhile); `agent` with `isolation: "worktree"` when sandboxed. `memory` never (it comes back in every session). A confined `bash` sees the project's `.git` read-only (git runs hooks and config from it *outside* the sandbox: the user's next commit would run a planted hook), and where there's no `.git` it gets an empty read-only placeholder there (`placeholders` in `sandboxArgs`: `--tmpfs` + `--remount-ro`; the empty mount point is `rmdir`ed afterwards), so it can't create a repository whose config would run on the user's next `git status`; if it fails on either (a `.git` path with "Read-only file system" in its output), Marv appends a hint to set `git_write: true`, which asks (and has its own `git:` scope). `ctx.yolo` carries into shared-folder subagents (`subagentContext`), so their safe calls run too and the rest ask, labeled. Known limits: a command can still change files the user later runs outside the sandbox (scripts, a nested repo's `.git`, `.envrc`); review with `git diff`.
- **Sandbox (`src/sandbox.ts`)**: `bash` runs inside bubblewrap: the system read-only, the home folder replaced by an empty one (toolchains like `~/.bun`, git config, and `~/.marv/skills` re-mounted read-only; credential files inside them, like `~/.cargo/credentials`, replaced by `/dev/null`; for a symlinked one (stow, chezmoi) the file it leads to is masked if a toolchain mount shows it, since bwrap can't mount on a symlink; tokens inside whole config files (`~/.gitconfig`, `~/.config/git/config`, `~/.cargo/config.toml`) can't be hidden), the project the only writable place (a caller can add `readOnly` folders, e.g. a worktree's shared `.git`; each is resolved through symlinks, since bwrap follows them, and refused if it is `/`, the home folder or a parent of it, or the project itself; a parent of the project (a worktree around a subagent working in its subfolder) is mounted *before* the project, so the project stays writable on top), bun's download cache a throwaway one per command (`BUN_INSTALL_CACHE_DIR=/tmp/bun-cache`, in the sandbox's private, RAM-backed `/tmp`), because a shared or host cache would let one sandboxed command (e.g. an install's lifecycle scripts) plant packages for another context; no network unless the call sets `network: true`, a cleared environment (no API keys), its own PID namespace (killing it kills everything it started). Output is stdout+stderr combined, capped (start and end kept); if bwrap itself fails to set the sandbox up, its error is shown as `[sandbox failed to start: …]` instead of empty output. `/sandbox off` runs commands directly (still approved, with a warning in the prompt); without bwrap the prompt warns too. Outside the sandbox commands start under `setsid` so a timeout or ctrl+c kills the whole process group.
- **Prompt cache (don't break it)**: providers reuse work for an identical prompt *prefix* (measured on Ollama: a follow-up turn's prompt in 76 ms instead of 1.2 s; one changed letter in the system prompt and it's back to 1.2 s). So: the system prompt is built once per session (`useMemo` in `App`), `toolSpecs` is a constant, `conversation` is only appended to (never edited or trimmed, except by compaction; `/clear` resets it), and adapters serialize deterministically. `tests/agent.test.ts` checks that every request extends the previous one exactly. The status bar shows the last request's size (`12.3k/32.8k ctx` when the window is known) and the cache hit rate when the provider reports it (OpenRouter); Marv warns once when Ollama's window is 85% full.
- **Provider seam (`src/provider/types.ts`)**: every provider implements `Provider.stream(history, { system, tools, signal }) → AsyncIterable<AgentEvent>` (`text_delta`, `thinking_delta`, `tool_call`, `usage`, `done`, `error`), converting its native stream into Marv's own events. The UI never sees a vendor format. Errors become `error` events with an actionable message (bad key → /setup, unknown model → /model, unreachable → is it running?). The system prompt lives in `src/prompt.ts`. Model lists for the picker come from `src/provider/models.ts` (OpenRouter `/models`, filtered to tool-capable; Ollama `/api/tags` + `/api/show`).
- **Rendering**: Marv runs full-screen in the terminal's alternate screen, so there is no terminal scrollback. Ink's options live in `src/render-options.ts`; keep `incrementalRendering: true`, because without it every update (each martian frame, each keystroke) erases and redraws the whole screen, which flickers in terminals like GNOME Console. `tests/render-options.test.tsx` guards this. The root `<Box>` is sized to the window; `ScrollView` (`src/ui/ScrollView.tsx`) takes the leftover height and scrolls the transcript itself (PgUp/PgDn or the mouse wheel, follows the bottom until you scroll up; `followKey` snaps back on submit). The prompt and status bar are pinned below it. Don't use `<Static>` here: in the alternate screen its output would scroll off and be lost. The whole transcript stays mounted, so **ink is patched** to skip drawing nodes entirely outside the visible (clipped) rows: unpatched, Ink wraps and draws every scrolled-away message on every frame, and a 60-entry session took ~270 ms per keystroke (now ~30 ms). `tests/render-performance.test.tsx` guards this. Wheel scrolling glides: notches add to a distance that a 20 ms timer covers a third at a time (at least a row), and Ink draws up to 60 frames/s (`maxFps: 60`); 20 ms keeps every step in its own frame (16 ms beat against Ink's limiter and stuttered). Two more patches keep frames cheap (~7 ms): **string-width is patched** (`patches/string-width@8.3.0.patch`) to cache widths and skip its per-character emoji regex for characters that can't be emoji (it was ~36% of CPU while scrolling; `tests/string-width.test.ts` pins its answers), and the Ink patch skips `findStaticNode`'s walk of the whole tree after every commit unless a `<Static>` was ever created. Text from the model or from files (replies, thinking, tool labels and summaries, approval previews, subagent steps) passes through `printable()` (`src/printable.ts`) before it's drawn: it strips escape sequences and control characters, which the terminal would execute rather than show (OSC 52 writes the clipboard, others retitle or redraw). Ink already drops them when it draws; this is defense in depth, applied at render time so the model's own conversation is untouched, and careful not to eat real text (UTF-8 misread as Latin-1 contains C1 bytes).
- **Mouse (`src/mouse.ts`)**: Ink has no mouse support, so Marv turns on SGR mouse reporting (mode 1002: presses, drags, wheel), wraps `stdin.read()` to strip mouse codes before Ink parses them, and emits `MouseEvent`s on the `mouse` emitter. Mouse mode is terminal-wide, so it is turned off in a `process.on("exit")` handler.
- **Selection (`src/selection.ts`, `src/clipboard.ts`)**: with mouse reporting on, the terminal can't select text, so Marv does: drag highlights, release copies (wl-copy / xclip / xsel / pbcopy, falling back to OSC 52), a click or any key clears it. The selection is stored in *transcript* rows, not screen rows (the transcript's `ScrollView` publishes its position and scroll via `onViewport`), so the highlight stays on its text while scrolling, and dragging past the top or bottom auto-scrolls. Only visible rows are ever drawn, so the store remembers each transcript row's text as it passes through the viewport and copies from that (like a terminal's scrollback); a resize or `/clear` resets it. **ink is patched** (`patches/ink@8.0.0.patch`, applied by `bun install`; edit with `bun patch ink`, then `bun patch --commit node_modules/ink`) with a `transformOutput(frame) → frame` render option, through which the store sees each frame and draws the highlight, and a `repaint()` that re-applies it to the last frame. Moving the highlight therefore costs ~3 ms instead of a full ~30 ms React render + layout + draw.
- **Slash commands (`src/commands/index.ts`)** are pure functions that return a `CommandAction` (`print` | `clear` | `setup` | `model` | `thinking` | `sandbox` | `yolo` | `trajectories` | `feedback` | `mcp-trust` | `skill` | `resume` | `compact` | `memory` | `remember` | `forget` | `exit`) and receive a read-only `CommandContext` (current config). The App applies the action. Add new commands to the `commands` array; they automatically show up in the `/` menu (`PromptInput`: ↑/↓ select, Enter runs the highlighted one, Tab or → completes so you can add arguments). A `print` action with `markdown: true` (e.g. `/skills`, `/agents`) is rendered through the Markdown renderer, so lists get hanging indents.
- **Replies are Markdown** (`src/ui/Markdown.tsx`): `marked.lexer()` turns the text into tokens and each becomes Ink boxes: list markers and quote bars sit in fixed-width columns (hanging indents), inline code is colored without backticks, code blocks get a left rule and their language, tables are aligned as plain text. While a reply streams (`streaming` prop), `createStreamLexer()` caches the blocks before the last safe boundary and re-parses only the unfinished end, because `marked` slows down faster than the text grows (~20 ms at 11 KB); finished messages are parsed whole once. An unclosed code fence renders fine mid-stream. The system prompt tells the model its replies are rendered as Markdown.
- **Tokens and cost (`src/usage.ts`)**: every request's `usage` event is added to session `Totals` (requests, input, cached and output tokens, cost). OpenRouter reports the real charge in `usage.cost` on every final chunk; without it the cost is estimated from the model's prices (`~$`), and Ollama is `local`. The App looks up the current OpenRouter model's context window and prices once (via `loadModels`), so the status bar shows context use there too. `/cost` prints the breakdown. Totals survive `/clear`.
- **Project keys (`projectKey` in `src/paths.ts`)**: per-project files (sessions, project memory, trajectories, MCP trust, worktrees) live under `<readable path>-<10-char hash of the full path>`; the readable part alone collided (`/a-b/c` vs `/a/b-c`, any two non-ASCII names of equal length), which made projects share memory, sessions and trusted MCP servers. Data under the old key (`legacyProjectKey`) is still found: sessions are read from both folders but only if their recorded `root` matches (and move on their next save), a project memory file is moved on load; old MCP trust is deliberately not carried over (those servers ask once more).
- **Sessions (`src/sessions.ts`)**: every conversation is saved to `~/.marv/sessions/<project>/<id>.json` (0600; written to a temp file then renamed) shortly after each turn ends: both histories (transcript and conversation), provider/model, and totals. `/clear` starts a new session. `/resume` (and `marv -r`) opens `SessionPicker`; `marv -c` restores the latest one here. Restoring brings back both histories and the cost, and keeps saving to the same file. The App takes `sessions` (a `SessionStore`) and `resume` props; without `sessions` nothing is saved (most tests).
- **Trajectories (`src/trajectory.ts`, `src/feedback.ts`, `src/trajectory-stats.ts`)**: every turn is logged, append-only, to `~/.marv/trajectories/<project>/<session id>.jsonl` (0600; one file per session, so `/clear` starts a new one and a resume continues it), for measuring Marv over time and as future training data. On by default (config `trajectories`, `/trajectories on|off`); the App takes a `TrajectoryStore` prop (none in most tests: nothing is logged). One JSON record per line, each with `v` (format version), `t`, `session`: `session` (once per file per process: Marv version, provider, model, the full system prompt, tool names, git HEAD), `turn_start`, then per agent `request` (usage, ms since the previous step ended), `assistant` (text + reasoning), `tool` (the call, exactly what the model got back, `approval`: `none`/`auto`/the answer, ms), `error`, `agent_end` (reason, steps, tools, ms); a subagent gets `subagent_start` and its own records under `agent: "<turn>.<n>"`. `compact` records the summary that replaced the history. `AgentRecorder` turns `LoopEvent`s into these records (main loop, and `AgentHost.onEvent` for subagents); `runTool` reports how a call was approved on `ToolResult.approval`. Feedback is a `feedback` record pointing to its turn: `/good [note]`, `/bad [note]`, `/label <tags>` (explicit, the last turn), and the user's next message, matched by `classifyReply` (keywords, negative checked first so a polite correction counts as one; the phrase is logged so it can be re-scored). Writes are queued (in order) and never throw into a run; the first failure is reported once. `bun run stats [--by model|marv]` prints turns, good rate (explicit rating wins over implicit), tokens and tools per turn, median time and how turns ended.
- **Compaction (`src/compact.ts`)**: when the last request used ≥85% of the context window (`COMPACT_AT`; known for Ollama and, via the model list, OpenRouter), `send()` first asks the model to summarize the conversation (`summarize`: same system/tools/history plus one instruction message, so it hits the prompt cache), then replaces `conversation` with `compactedHistory(summary)` and continues. A reply that calls a tool (the tools are offered, for the cache) or stops at the output limit isn't a summary: `summarize` returns an error and the history is kept. `/compact [focus]` does it on demand; Esc cancels it with nothing changed. The transcript is never touched, and the summary request counts toward tokens and cost. This is the one deliberate exception to "never rewrite the history": the cache starts over once.
- **Render budget**: `App.send()` batches streamed tokens and reaches React at most every 33 ms (`STREAM_FLUSH_MS`, matching Ink's 30 fps cap), flushing immediately at step ends; subagents' progress joins the same flush; `MessageView` and `Transcript` are memoized so a transcript change only re-renders the entries that changed. `tests/render-performance.test.tsx` guards keystroke cost and stream batching (also with 4 subagents reporting).
- Colors live only in `src/ui/theme.ts`. Message markers (`●`, `>`) sit in a fixed 2-column `Gutter` box: a Text with a trailing space (`"● "`) is laid out 1 column narrower than it's drawn, so the text beside it overflows and loses a character per wrap (`tests/messageview.test.tsx`).

## Conventions

- Imports use explicit `.ts`/`.tsx` extensions (`allowImportingTsExtensions` + `verbatimModuleSyntax`; use `import type` for types).
- UI tests use `ink-testing-library`. Pass `splashMs={0}` to skip the splash, `makeProvider={() => new FakeProvider()}` (`tests/fake-provider.ts`) for an instant, offline stream (or a `ScriptedProvider` to script tool calls step by step), a `root` temp dir for the tools, and a `ConfigStore` on a temp dir.
- Providers: OpenRouter (default model `anthropic/claude-sonnet-5.5`) and Ollama (local, no key). A saved provider Marv no longer knows (e.g. the removed `echo`) is dropped on load, which reopens setup. Tests never hit the network: the adapters are tested against a local `Bun.serve`, and `App` takes `loadModels`/`makeProvider` props.
